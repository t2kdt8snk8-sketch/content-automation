# 프론트엔드 에셋 및 레이아웃 무결성 적용 플랜 (Frontend Execution Plan)

본 문서는 새롭게 배경이 제거된 에셋(가구, 캐릭터)을 픽셀 오피스 엔진에 적용하고, 에러 없이 프론트엔드가 구동되도록 보장하기 위한 단계별 실행 계획입니다.

## 1. 투명화된 에셋 덮어쓰기 (Asset Replacement)
- **대상**: 새롭게 식물까지 복원하여 이름이 매칭된 배경 투명화 PNG 파일들.
- **방식**: 기존 픽셀 오피스의 `web/frontend/public/assets/` (캐릭터 스프라이트, 가구 폴더 등) 내부 경로에 맞춰 **파일명과 크기(규격)를 똑같이 유지**하여 덮어쓰기 합니다.
- **무결성 체크**: `furniture-catalog.json`에 명시된 가로/세로 규격(`width`, `height`, `footprintW`, `footprintH`)과 실제 이미지 크기가 일치해야 엔진이 스프라이트를 정확히 분할하여 렌더링할 수 있습니다. (신규 추가 에셋의 경우 카탈로그에 새로 등록 필요)

## 2. '튀어나온 벽' 및 커스텀 레이아웃 도면 설계 (Layout Engineering)
- **에셋 유지**: 벽 타일은 추가 렌더링 에러를 방지하기 위해 기존 `wall_0.png` 에셋을 100% 재활용합니다.
- **도면 수정 (`default-layout-1.json`)**:
  - `tiles` 배열에서 파티션이나 튀어나온 벽 구조가 필요한 좌표에 숫자 `0`을 찍어 렌더링과 물리 충돌 판정을 일치시킵니다.
- **🚨 커스텀 배치 전략 (완성본과 차이점 반영)**:
  1. **오른쪽 방 테이블 이동**: 기존 완성본 이미지에 있던 오른쪽 방 직원들 테이블의 y좌표(row)를 아래로 충분히 이동시킵니다.
  2. **사장님 책상 배치**: 완성본에는 없었던 '사장 책상'을 새로 확보된 공간(화이트보드와 오른쪽 방 테이블 사이)에 배치합니다.
  3. **공간 여유(Space) 검증**: 사장 책상과 직원 테이블 사이에 에이전트들이 걸어 다닐 통로(1~2칸)가 충분히 나오는지 확인합니다. 공간이 부족할 경우 전체 맵의 `rows`를 늘리거나 파티션 위치를 위로 올리는 방안을 고려합니다.
  4. **에셋 차이 보정**: 실제 들어가는 에셋의 크기나 모양이 완성본 레퍼런스 이미지와 살짝 다를 수 있으므로, 각 에셋의 실제 `footprint`(타일 점유 면적)에 맞춰 간격을 미세 조정합니다.

## 3. UI 조작 버그 및 크래시 예방 (Crash Prevention)
에셋 적용 후 클릭 인터랙션에서 프론트엔드가 뻗지 않도록 다음 사항들을 적용(또는 우회)합니다.

- **미등록 에이전트 클릭 크래시 방지**: `OfficeCanvas.tsx`에서 백엔드의 WebSocket 통신이 오기 전에 캐릭터를 클릭하면 `agentIdMap`에 ID가 없어 앱이 죽는 이슈가 있습니다. 이를 방지하기 위해 초기 스폰되는 모든 에이전트 ID(1~7)를 명시적으로 하드코딩 매핑해 둡니다.
- **벽걸이 가구(화이트보드) 힛박스 보정**: 벽(`0` 타일)에 배치되는 가구는 시각적인 위치(y 좌표)와 실제 물리적으로 점유하는 타일 위치가 다를 수 있습니다. `getFurnitureAt` 함수에서 클릭 마우스 좌표 판별 시 y축 row 보정값(offset)을 적용하여 클릭이 무시되지 않도록 합니다.
- **캔버스 정렬**: 화면 최상단에서부터 오피스가 시작되도록 컨테이너 레이아웃을 `alignItems: 'flex-start'`, `paddingTop: 80px` 등으로 조정하여 오버레이 UI와의 간섭을 최소화합니다.

## 4. 실행 순서 요약
1. 현재 `public/assets/` 내 기존 파일들 백업 (안전성 확보)
2. 직접 이름 변경 및 매칭한 파일들을 `public/assets/...` 내부로 복사 및 덮어쓰기 (또는 신규 등록)
3. 완성본 구조 + 사장 책상 커스텀 배치를 반영하여 `default-layout-1.json` 도면 및 가구 좌표 수정
4. 앱 실행 및 브라우저에서 충돌(Collision), 동선, 클릭 인터랙션 검증
