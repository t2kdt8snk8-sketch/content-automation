# Content Automation Frontend V3 개편 플랜 (Virtual Agency UX)

## 1. 핵심 철학: "Agent-Centric Interface (직원 중심 인터페이스)"
기존의 기능 중심 '탭(Tab)' 구조를 완전히 폐기하고, 사용자가 실제 에이전시의 국장이 되어 가상 사무실에서 직원들과 소통하며 일하는 몰입형 경험을 제공합니다. 화면의 메뉴 버튼 대신, **사무실 내의 사물(가구)과 캐릭터를 클릭하여 시스템을 조작**합니다.

## 2. 전체 레이아웃 (The War Room)
- **배경**: 브라우저 화면의 100%를 `OfficeCanvas` (픽셀 오피스)가 채웁니다.
- **오버레이 (Overlay) UI**: 캔버스 위의 특정 오브젝트를 클릭했을 때만, 그에 맞는 패널(채팅창, 대시보드 모달 등)이 반투명한 레이어 형태로 부드럽게 팝업됩니다. 평소에는 사무실 전경만 보여 몰입감을 극대화합니다.

## 3. 오피스 내 인터랙션 맵 (GNB 대체)
기존의 상단 메뉴바나 탭 버튼은 오피스 공간 내의 클릭 이벤트로 대체됩니다. (`OfficeState.ts`의 `getCharacterAt`을 활용하고, 가구를 위한 `getFurnitureAt` 로직을 신설하여 구현)

### 3.1. 💻 사장님 책상 (My Desk)
- **대상**: 국장님 자리의 모니터/키보드 (가구 오브젝트)
- **클릭 시 액션**: 화면 우측에서 **[팀 통합 채팅방 (Slack)]**이 슬라이드되어 나옵니다.
- **용도**: 레이, 샐리, 제이크에게 말로 업무를 지시하고 보고를 받는 핵심 컨트롤 타워입니다. 사용자가 직접 제작을 시작하고 싶을 때도 여기서 지시를 내리거나 에디터를 호출합니다.

### 3.2. 📈 벽면 전광판 (The Big Board)
- **대상**: 사무실 벽의 메인 대시보드 모니터 (`WHITEBOARD` 에셋 활용)
- **클릭 시 액션**: 화면 중앙에 큼직한 **[통합 칸반 보드 모달]**이 열립니다.
- **용도**: 전체 리서치 수집량, 기회 카드(기획안) 목록, 현재 제작 중인 콘텐츠 현황을 한 화면에서 Trello처럼 조망하는 관리자 전용 통합 뷰입니다.

### 3.3. 🕵️‍♂️ 레이 (리서처) 캐릭터 클릭
- **클릭 시 액션**: 레이의 작업물인 **[리서치 전용 뷰]**가 팝업됩니다.
- **용도**: 백엔드에서 긁어온 뉴스, 트렌드, 레딧 반응 원본 데이터를 확인합니다.

### 3.4. 🧠 샐리 (전략가) 캐릭터 클릭
- **클릭 시 액션**: 샐리가 보고하는 **[기획안 결재 뷰]**가 팝업됩니다.
- **용도**: AI가 제안한 기회 카드를 보고 '제이크에게 제작 지시(Approve)' 또는 '반려(Pass)'를 결정합니다.

### 3.5. ✍️ 제이크 (에디터) 캐릭터 클릭
- **클릭 시 액션**: 텍스트 에디터가 포함된 **[제작 스튜디오]**가 팝업됩니다.
- **용도**: 제이크가 쓴 대본 초안을 수정하거나, 국장님이 백지상태에서 직접 글을 쓸 때 사용합니다. 채팅창과 연동하여 실시간 피드백을 반영합니다.

## 4. 기술적 구현 마일스톤 (React + Canvas)

### Phase 1: 캔버스 인터랙션 및 hit-test 기반 마련
1. **`OfficeState.ts`에 가구 클릭 판정 로직 추가**:
   - 이미 존재하는 `getCharacterAt(worldX, worldY)`에 더하여, 타일 기반으로 가구를 찾는 `getFurnitureAt(worldX, worldY)` 메서드를 신설합니다.
   - `worldX / TILE_SIZE`, `worldY / TILE_SIZE`로 타일 좌표(col, row)를 계산한 뒤, `this.furniture` 배열을 순회하며 해당 타일에 위치한 가구(예: `PC`, `WHITEBOARD`)의 `uid` 또는 `type`을 반환하게 합니다.
2. **`OfficeCanvas.tsx`에 이벤트 리스너 연동**:
   - `<canvas>` 태그에 `onClick`과 `onMouseMove` (커서 포인터 변경용) 이벤트를 추가합니다.
   - `e.nativeEvent.offsetX / ZOOM` 등의 계산식을 통해 마우스 좌표를 픽셀 월드 좌표로 변환합니다.
   - 변환된 좌표로 `stateRef.current.getCharacterAt()` 및 `getFurnitureAt()`을 호출하여 무엇을 클릭했는지 식별합니다.

### Phase 2: 레이아웃 뼈대 및 전역 오버레이 상태 관리 개편
1. **App.tsx 상태 관리 개편 (`useState`)**:
   - 오버엔지니어링을 피하기 위해 기존 `useState` 구조를 유지하되, `activeTab`을 `activeOverlay: 'chat' | 'dashboard' | 'research' | 'opportunity' | 'production' | null` 상태로 교체합니다.
2. **OfficeCanvas 콜백 연동**:
   - `OfficeCanvas` 컴포넌트에 `onOverlayOpen={(overlay) => setActiveOverlay(overlay)}` 형태의 prop 콜백을 내려줍니다.
   - 캐릭터 매핑: 클릭 판정된 캐릭터 ID에 따라 각각 'research'(레이), 'opportunity'(샐리), 'production'(제이크) 오버레이를 열도록 콜백을 호출합니다.
   - 가구 매핑: 사장님 자리의 `PC` 클릭 시 'chat', 벽면의 `WHITEBOARD` 클릭 시 'dashboard'를 엽니다.
3. **레이아웃 계층화 (z-index)**:
   - 최상단 `App.tsx` 또는 컨테이너에서 `<OfficeCanvas />`를 `absolute inset-0 z-0`으로 깔아 전체 배경으로 만듭니다.
   - 그 위에 `<OverlayManager />` 컴포넌트를 `z-10` 이상으로 띄워 `activeOverlay` 상태에 따라 알맞은 패널을 렌더링합니다.

### Phase 3: 오버레이 UI(팝업) 디자인 적용 및 재사용
1. **기존 컴포넌트 리팩토링 (`ChatPanel`, `FeedPanel`, `ProductionPanel` 등)**:
   - 이 컴포넌트들을 재활용하되, 전체 화면을 가리지 않도록 디자인을 리팩토링합니다. 
   - 배경 화면(오피스)이 은은하게 비치도록 Glassmorphism (반투명 및 배경 블러 `backdrop-blur`) CSS를 적용합니다.
   - 오버레이를 닫을 수 있는 명시적인 닫기(X) 버튼을 추가하거나, 오버레이 바깥(캔버스 영역)을 클릭 시 닫히는 로직을 추가합니다.
2. **신규 대시보드 컴포넌트 개발**:
   - 전광판(`WHITEBOARD`) 클릭 시 나타날 '통합 대시보드(상황판)' 컴포넌트를 신규로 개발하여 전체 작업 현황을 볼 수 있게 연동합니다.

## 5. 최종 기대 효과
이 개편을 통해 시스템은 단순한 '버튼과 탭으로 이루어진 툴'을 넘어서 완벽한 '가상 에이전시 시뮬레이터'로 거듭납니다. 사용자는 복잡한 UI를 조작하는 피로감 없이, 공간과 캐릭터라는 직관적인 맥락(Context)을 통해 업무를 지시하고 통제할 수 있습니다.
