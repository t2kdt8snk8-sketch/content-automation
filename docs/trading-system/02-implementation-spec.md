# 구현 스펙 (Implementation Spec) — 미국 주식 스윙 자동매매 시스템

> **이 문서는 구현자(GPT 5.5)를 위한 설계 브리프다.**
> 코드를 여기서 다 짜놓지 않는다. **요구사항·아키텍처 방향·반드시 지킬 규칙·흔한 함정**을 정의하고,
> 구체적인 구현 결정(라이브러리 세부, 함수 시그니처, 클래스 설계 등)은 구현자에게 위임한다.
> 운영 로드맵은 `01-execution-plan.md` 참고.

---

## 0. 목표 (구현이 만족해야 할 것)

1. 미국 주식/ETF 대상 **스윙(보유 하루~수주) 자동매매** 시스템.
2. **백테스트 → 워크포워드 검증 → Alpaca 페이퍼 자동 운영 → 텔레그램 리포트**까지 한 흐름.
3. **백테스트와 실거래가 동일한 전략 코드를 공유**해야 한다 (괴리 방지).
4. 폰만으로 운영·모니터링 가능해야 한다 (클라우드 자동 실행).

## 2. 아키텍처 (모듈 책임 정의 — 코드는 구현자 재량)

```
trading/
  config.py              # 모든 설정 한 곳: 유니버스, 전략 파라미터, 리스크 한도
  data.py                # 가격 수집 (백테스트/실거래 공통 인터페이스)
  strategies/
    base.py              # 전략 공통 규격 (입력: 가격 → 출력: 목표 포지션)
    breakout.py          # 전략 후보 ① 모멘텀/변동성 돌파
    mean_reversion.py    # 전략 후보 ② RSI 평균회귀
  backtest/
    engine.py            # 벡터화 백테스터 (비용/슬리피지/세금 반영)
    metrics.py           # CAGR, MDD, Sharpe, 승률
    walkforward.py       # 안 본 구간 검증 (과최적화 필터)
  live/
    broker.py            # Alpaca 페이퍼 래퍼 (포지션 조회 / 주문)
    notify.py            # 텔레그램 리포트
    run_daily.py         # 스케줄러 진입점
  reports/               # 백테스트 결과·그래프 산출물
.github/workflows/
  trade.yml              # cron 스케줄
requirements.txt
README.md                # 셋업·운영 매뉴얼 (사용자가 폰으로 봄)
```

### 관심사 분리 원칙
- **전략(strategies)** 은 "오늘까지의 가격 → 목표 포지션"만 책임진다. 비용·주문·실행은 모른다.
- **백테스트 엔진**과 **실거래 broker**가 그 목표 포지션을 각자의 방식으로 실현한다.
- → 같은 전략 코드가 백테스트와 실거래에서 그대로 재사용된다.

## 3. 동작 흐름 (실거래 일일 루프)

```
GitHub Actions cron (미국장 마감 후 자동 실행)
  1. data.py     : 최신 일봉 수집
  2. strategy    : 신호 계산 (오늘 데이터까지만 사용)
  3. broker.py   : Alpaca 현재 포지션 조회 → 목표와 비교 → 차이(델타)만 주문
  4. notify.py   : 텔레그램 리포트 ("오늘 매매 + 현재 성적")
  5. 로그 기록
```

- **상태(보유 종목)의 진실원천은 Alpaca 계좌**다. 코드가 별도 상태를 들고 있다가 꼬이지 않게 한다.

## 4. 반드시 지킬 규칙 (어기면 백테스트가 거짓말을 한다)

> 이 섹션이 이 문서에서 가장 중요하다. 구현자는 아래를 **명시적으로 코드에 반영**할 것.

1. **미래참조(lookahead) 금지**
   - 신호는 시점 `t`까지의 데이터로만 계산하고, **체결은 `t+1` 시가**로 가정한다.
   - 종가를 보고 그 종가에 산다고 가정하는 것은 금지(현실에선 불가능).
2. **거래비용 반영**
   - 수수료, **슬리피지**(원하는 가격에 못 잡히는 손해), 세금을 백테스트에 반드시 포함.
   - 비용 0 가정 백테스트는 무효로 간주.
3. **생존편향(survivorship bias) 주의**
   - 지금 살아있는 종목만으로 과거를 테스트하면 결과가 부풀려진다. 유니버스 구성 시 인지할 것.
4. **워크포워드 / 아웃오브샘플 검증 필수**
   - 과거 일부 구간으로 파라미터를 정하고, **그 구간을 보지 않은 미래 구간**에서 성능을 측정한다.
   - 인샘플만 좋고 아웃오브샘플에서 무너지면 = 과최적화 = **탈락**.
5. **벤치마크 비교 의무**
   - 모든 결과는 **SPY 매수후보유(적립식)** 와 나란히 비교 출력한다.
6. **파라미터 최소화**
   - 조건/변수가 많을수록 과최적화 위험이 커진다. **단순함을 우선**한다(구현자가 임의로 복잡도를 늘리지 말 것).

## 5. 전략 후보 (2종 비교 — 어느 게 우월한지는 검증이 결정)

> 두 전략을 **워크포워드로 정면 비교**하고, 살아남는 쪽을 채택한다. 둘 다 게이트 미달이면 다음 가설로.

- **① 모멘텀 / 변동성 돌파 (breakout.py)**
  - 개념: 가격이 일정 변동폭을 상향 돌파하면 추세로 보고 진입, 며칠 보유.
  - 강점: 추세장. 약점: 횡보장 휘프소(속임수 신호).
- **② RSI 평균회귀 (mean_reversion.py)**
  - 개념: 과도하게 하락한(과매도) 종목을 매수, 반등하면 청산. 보유 며칠.
  - 강점: 횡보/되돌림 장. 약점: 추세 하락장에서 물림.

> 정확한 파라미터 값(룩백 기간, 임계값, k 등)은 **하드코딩하지 말고 `config.py`에 노출**하고, 워크포워드로 결정할 것.

## 6. 리스크 관리 (1단계부터 내장)

- 종목당 최대 비중 한도, 동시 보유 종목 수 제한.
- 손절(스톱로스) / 최대 보유일수 초과 시 강제 청산.
- 전체 노출 한도.
- **킬스위치**: 이상 상황(데이터 오류, 과도한 손실 등) 감지 시 전 종목 청산 + 운영 중단.
- 모든 리스크 파라미터는 `config.py`에서 관리.

## 7. 보안 / 운영
