# 군 복무 중 학습형 AI 투자 보조 전략 문서

> 목적: 군 복무 18개월 동안 직접 대응 시간이 제한된 상황에서도 AI를 투자 분석가처럼 훈련시키고, 최종 결정은 사람이 승인하는 반자동 매매 보조 시스템을 설계한다.

이 문서는 투자 조언이 아니라 시스템 설계 문서다. 실제 돈을 넣기 전에는 군 복무 중 투자/자동매매 가능 범위, 증권사 API 약관, 세금, 계좌 보안, 자동 주문 책임 범위를 직접 확인해야 한다. AI의 추천은 투자 판단 참고자료일 뿐이고, 최종 책임은 항상 승인자에게 있다.

---

## 1. 핵심 결론

만들어야 하는 것은 "LLM이 알아서 사고파는 봇"이 아니다.

목표 시스템은 아래에 가깝다.

```text
검증된 데이터
+ 가격/거래/이벤트 피처
+ LLM 기반 대안 데이터 구조화
+ supervised alpha model
+ AI 투자 의견서 생성
+ 사람의 최종 승인
+ 강화학습 모의투자 연구실
+ 벤치마크 상대 위험관리
+ 제한된 주문 보조
```

LLM은 최종 주문자가 아니다. 하지만 단순 데이터 정리 담당으로만 둘 필요도 없다. LLM은 투자 분석가처럼 종목 후보를 설명하고, 반대 논리를 만들고, 리스크를 정리하고, 매수/매도/보류 의견서를 작성하는 역할까지 맡을 수 있다.

핵심 원칙은 아래다.

```text
AI가 판단안을 만든다.
수학 모델과 위험관리 규칙이 검증한다.
사람이 최종 승인한다.
승인 없이는 실전 주문하지 않는다.
```

강화학습은 초반부터 연구해도 된다. 다만 실전 투입은 늦게 해야 한다. 군 복무 18개월은 실전 돈을 걸기보다 모의투자 환경에서 강화학습을 오래 검증하기 좋은 시간이다.

## 2. 현실 제약

### 2.1 군 복무 중 제약

군 복무 중에는 장중 대응이 어렵다. 그래서 초단타, 고빈도 매매, 장중 수동 개입이 필요한 전략은 맞지 않는다.

시스템은 아래 조건을 전제로 설계해야 한다.

- 매일 코드를 길게 수정하기 어렵다.
- 장중 급락에 바로 대응하기 어렵다.
- 서버 장애를 즉시 고치기 어렵다.
- 주문 오류가 나도 바로 확인하지 못할 수 있다.
- 보안 사고가 나면 계좌 피해가 직접 발생한다.

따라서 실전 시스템은 저빈도, 자동 정지 가능, 설명 가능한 구조여야 한다.

### 2.2 LLM 역할과 한계

LLM은 다음 일을 잘한다.

- 뉴스, 공시, 실적콜 요약
- 문서에서 이벤트 추출
- 경영진 발언 톤 변화 분석
- 리스크 문구 변화 감지
- 투자 아이디어의 근거와 반대 근거 정리
- 종목별 매수/보류/매도 의견서 작성
- 모델 점수와 실제 뉴스 흐름의 충돌 여부 확인
- 백테스트 결과 설명
- 오류 로그 해석 보조

LLM은 다음 일을 맡기면 안 된다.

- 사람 승인 없는 실시간 매수/매도 최종 판단
- API 키 접근
- 손절/익절 규칙 임의 변경
- "오늘 분위기 좋음" 같은 주관적 주문
- 검증되지 않은 전략 자동 배포

쉽게 말하면 LLM은 투자 분석가다. 단독 트레이더는 아니다.

### 2.3 AI 투자 전문가 보조 모드

이 시스템의 실전 가치는 AI가 매매 버튼을 대신 누르는 데서 나오지 않는다. 가치는 사람이 보기 어려운 많은 정보를 압축해서, 더 나은 결정을 하게 돕는 데서 나온다.

AI는 매일 아래 형식의 투자 의견서를 만든다.

```text
추천: 매수 / 보류 / 매도 / 관찰
확신도: 0~100
예상 보유 기간: 며칠~몇 주
핵심 근거 3개
반대 근거 3개
상승 시나리오
하락 시나리오
진입 가격대
손절 기준
익절 또는 재평가 기준
예상 기대값
최대 허용 비중
거래하면 안 되는 조건
```

중요한 점은 AI가 항상 반대 근거를 함께 내야 한다는 것이다. 좋은 투자 분석가는 매수 논리만 말하지 않는다. 틀릴 수 있는 이유를 같이 말한다.

### 2.4 AI 의견서 일관성 확보

AI 의견서는 말투가 아니라 구조가 중요하다. 같은 상황에서 매번 다른 기준으로 판단하면 투자 전문가가 아니라 흔들리는 조언자가 된다.

일관성을 위해 아래 네 가지를 고정한다.

```text
1. 의견서 양식
2. 점수 계산 기준
3. 입력 데이터 기준일
4. 사후 채점 방식
```

의견서는 항상 같은 항목을 같은 순서로 작성한다. 항목이 비어 있으면 추천 강도를 낮춘다.

AI가 쓰는 설명용 점수는 감으로 주지 않는다. 다만 이 점수는 최종 매매 판단 숫자가 아니라 저렴한 후보 선별용 필터다. 최종 판단 숫자는 시스템이 계산한 `EV`, `p_break_even`, `p_calibrated`, `reward_risk`, `math_score`다.

```text
가격/추세: 최대 20점
실적/재무: 최대 20점
뉴스/이벤트: 최대 20점
수급/거래량: 최대 15점
손익비: 최대 25점
리스크: 최대 -20점
```

이 기준표는 처음부터 완벽할 필요는 없다. 중요한 것은 같은 기준을 계속 써서 후보를 좁히고, 실제 승인 단계에서는 수학 검증값으로 다시 막는 것이다. AI는 이 숫자를 해석하고 반대 근거를 쓰는 역할이지, `math_score`나 기대값을 새로 만들어내는 역할이 아니다.

최종 수학 검증은 아래를 본다.

```text
p_break_even = (loss + cost) / (gain + loss)
EV = p_calibrated * gain - (1 - p_calibrated) * loss - cost
reward_risk = gain / loss
```

실전 승인 최소 조건:

```text
p_calibrated가 존재해야 함
EV > 0
p_calibrated >= p_break_even + 0.05
reward_risk >= 1.5
0.5% 비용 스트레스에서도 EV가 양수
```

의견서마다 아래 정보도 함께 저장한다.

- 작성 시각
- 사용한 모델 이름
- 프롬프트 버전
- 데이터 기준일
- 사용한 주요 데이터 출처
- 추천 점수
- 수학 점수와 기대값
- 손익분기 확률과 보정 확률
- 최종 사람 승인 여부
- 이후 5일, 10일, 20일 성과

같은 입력을 다시 넣었을 때 결과가 크게 달라지는지도 본다. 예를 들어 같은 날짜의 같은 종목을 다시 분석했는데 한 번은 92점 매수, 한 번은 61점 보류가 나오면 실전 판단에 쓰면 안 된다.

출처 없는 주장은 의견서에 넣지 않는다. "좋아 보임", "시장 관심이 많음" 같은 표현은 숫자, 뉴스, 공시, 차트 조건 중 하나로 연결되어야 한다.

### 3.1 권장 실행 엔진: QuantConnect LEAN

백테스트와 주문 실행 엔진은 처음부터 직접 만들지 않는다. 가능하면 QuantConnect의 오픈소스 엔진인 LEAN을 쓴다.

LEAN에 맡길 것:

- 백테스트
- paper trading
- 실전 주문 실행
- 포트폴리오 상태 관리
- 수수료/체결 시뮬레이션
- 브로커 API 연결

직접 만들 것:

- 데이터 수집
- LLM 이벤트 피처 생성
- ML/RL 모델 학습
- 위험관리 규칙
- 일별/주별 리포트
- 킬스위치 조건

추천 구조:

```text
외부 Python 프로젝트:
데이터 수집 -> LLM 구조화 -> 모델 학습 -> 예측 파일 생성

QuantConnect LEAN:
예측 파일 로드 -> 백테스트 -> paper trading -> 제한 실전 주문
```

QuantConnect는 두뇌가 아니라 엔진이다. 알파는 데이터와 모델에서 나오고, LEAN은 그 전략을 같은 규칙으로 검증하고 실행하는 역할을 맡는다. 초반에는 실전 자동 주문보다 모의투자와 주문 예정 목록 검증에 더 많이 쓴다.

## 4. 데이터 전략

### 4.1 데이터 품질이 모델보다 중요하다

과거 차트를 모두 학습한다고 해서 좋은 모델이 되는 것은 아니다. 잘못된 데이터로 학습하면 모델은 과거의 착시를 배운다.

반드시 확인해야 할 데이터 항목:

- 수정주가: 액면분할, 병합, 배당 등을 반영한 가격
- 상장폐지 종목: 망한 종목까지 포함해야 생존자 편향을 줄일 수 있음
- 거래정지 기록: 실제로는 팔 수 없던 기간을 반영해야 함
- 종목 변경 이력: 티커 변경, 합병, 분할
- 거래비용: 수수료, 세금, 환전 비용
- 슬리피지: 생각한 가격과 실제 체결 가격 차이

생존자 편향은 초보자가 가장 많이 놓치는 문제다. 현재 살아남은 종목만 가지고 10년 백테스트를 하면, 과거에 망한 회사가 빠져서 수익률이 과장된다.

### 4.2 데이터 소스 단계

처음부터 비싼 데이터를 살 필요는 없다. 데이터 파이프라인과 검증 엔진이 먼저다.

| 단계 | 목적 | 데이터 수준 | 비용 감각 |
|---|---|---|---|
| 0단계 | 구조 만들기 | 무료 데이터, 제한된 API | 무료 |
| 1단계 | 일봉 연구 | 수정주가 포함 EOD 데이터 | 월 수만 원 |
| 2단계 | 정밀 검증 | 상장폐지 포함, intraday 일부 | 월 수만~수십만 원 |
| 3단계 | 대안 데이터 | 뉴스, 공시, 옵션, 애널리스트 | 더 비쌈 |

후보 데이터 소스:

- Alpaca: API 연결과 미국 주식 기본 데이터 실험에 유용
- Polygon.io: 미국 주식/옵션/실시간 데이터 쪽에서 많이 사용
- EODHD: 일봉, 조정주가, 상장폐지 데이터 접근에 유리
- Financial Modeling Prep: 재무제표, 가격, 일부 기업 데이터
- Nasdaq Data Link / Sharadar: 더 정교한 연구용 데이터 후보

정확한 가격은 자주 바뀐다. 결제 전 공식 가격표와 제공 필드를 다시 확인해야 한다.

### 4.3 데이터 버전 관리

같은 전략을 다시 돌렸는데 결과가 달라지면 안 된다.

그래서 데이터는 다음 정보를 함께 저장해야 한다.

- 수집 일시
- 데이터 제공자
- 조정 방식
- 원본 파일 해시
- 결측치 처리 방식
- 사용한 종목 유니버스

## 5. 피처 전략

### 5.1 클래식 피처의 위치

이동평균, RSI, MACD, 거래량 급증 같은 피처는 버릴 필요는 없다. 하지만 이것만으로 알파를 기대하면 약하다.

이 피처들의 역할은 baseline이다. 즉, 모델이 최소한 시장의 기본 상태를 이해하도록 하는 기본 입력값이다.

클래식 피처 예시:

- 1일, 5일, 20일, 60일 수익률
- 단기/장기 변동성
- 거래대금 변화
- 신고가/신저가 근접도
- 시장지수 대비 상대강도
- 갭 상승/하락
- 섹터 ETF 대비 초과수익

### 5.2 핵심은 LLM 기반 대안 데이터

진짜 차별화 가능성이 있는 부분은 텍스트와 이벤트 데이터다.

LLM은 아래 문서를 읽고 구조화된 이벤트로 바꾼다.

- SEC 10-K, 10-Q, 8-K
- 실적 발표 자료
- 실적콜 transcript
- 가이던스 상향/하향 발표
- 제품 출시
- 리콜, 소송, 규제 이슈
- 내부자 매수/매도
- 애널리스트 목표가 변경
- 경쟁사 이벤트
- 공급망 관련 뉴스

예시 출력:

```json
{
  "ticker": "AAPL",
  "event_date": "2026-04-30",
  "available_at": "2026-04-30T16:32:00-04:00",
  "usable_from": "2026-05-01 market_open",
  "event_type": "earnings_call",
  "guidance_change": "lowered",
  "management_tone": -0.34,
  "uncertainty_score": 0.72,
  "product_momentum": 0.18,
  "litigation_risk": 0.12,
  "margin_pressure": 0.66,
  "summary_confidence": 0.81
}
```

이 데이터는 바로 주문에 쓰지 않는다. 가격 데이터와 합쳐서 모델 입력값으로 사용한다.

여기서 가장 중요한 값은 `available_at`이다. `event_date`는 사건이 일어난 날짜이고, `available_at`은 내가 실제로 그 정보를 알 수 있었던 시간이다. 모델은 `available_at` 이후의 거래에만 이 정보를 쓸 수 있다. 이걸 지키지 않으면 모델이 미래 정보를 훔쳐본 것처럼 학습한다.

### 5.3 이벤트 피처 설계

좋은 이벤트 피처는 "무슨 일이 있었는가"와 "시장이 보통 그 사건에 어떻게 반응했는가"를 분리한다.

예시:

- `event_type`: 실적 발표, 가이던스 변경, 소송, 제품 발표
- `tone_delta`: 이전 문서 대비 긍정/부정 톤 변화
- `uncertainty_delta`: 불확실성 표현 증가/감소
- `risk_factor_change`: 10-K/10-Q 리스크 문구 변화
- `analyst_revision_count`: 최근 30일 목표가 상향/하향 수
- `event_surprise`: 시장 예상과 실제 이벤트 차이
- `sector_spillover`: 같은 섹터 종목에 미치는 영향

## 6. 라벨링 전략

### 6.1 단순 상승/하락 라벨은 약하다

나쁜 라벨 예시:

```text
내일 종가가 오르면 1, 내리면 0
```

이 방식은 실제 매매와 거리가 멀다. 손절, 익절, 보유기간, 거래비용이 반영되지 않는다.

### 6.2 Triple-barrier labeling

더 나은 방식은 triple-barrier labeling이다.

고정된 `+4%`, `-2%` 같은 값은 처음 설명용으로는 쉽지만 실전에는 약하다. 종목마다 변동성이 다르기 때문이다. 테슬라의 4% 움직임과 코카콜라의 4% 움직임은 의미가 다르다.

더 현실적인 방식:

```text
진입 후 10거래일 안에
+2.0 * 최근 변동성 도달하면 성공
-1.0 * 최근 변동성 도달하면 실패
둘 다 아니면 시간 종료
```

이 방식은 실제 거래 규칙과 더 비슷하다.

이 라벨은 모델이 "오를지"가 아니라 "정해진 위험 대비 보상이 나올지"를 배우게 만든다.

### 6.3 Meta-labeling

1차 모델은 후보를 찾는다. 2차 모델은 그 후보가 실제로 거래할 만한지 걸러낸다.

```text
1차 모델: 이 종목에 기회가 있는가?
2차 모델: 이 신호를 믿고 돈을 걸어도 되는가?
```

이 방식은 신호가 너무 많이 나오는 문제를 줄이는 데 도움 된다.

## 7. 모델 전략

### 7.1 Baseline

처음에는 반드시 단순한 기준 모델을 만든다.

예:

- 동일가중 포트폴리오
- SPY/QQQ buy and hold
- 단순 모멘텀
- 랜덤 매수 모델
- 로지스틱 회귀

복잡한 모델이 단순 모델보다 못하면 버려야 한다.

### 7.2 Supervised alpha model

초기 실전 후보는 supervised model이 맞다. supervised model은 과거 입력과 결과를 보고 규칙을 학습하는 방식이다.

추천 순서:

1. Logistic Regression
2. Random Forest
3. LightGBM
4. XGBoost
5. CatBoost

딥러닝은 나중에 붙인다. 이유는 금융 데이터가 시끄럽고, 딥러닝은 과거 데이터에 너무 잘 맞춰지는 문제가 크기 때문이다.

### 7.3 강화학습

강화학습은 연구를 일찍 시작한다. 실전 투입은 늦게 한다.

강화학습이 맡기 좋은 영역:

- 포지션 크기 조절
- 진입/청산 타이밍
- 리밸런싱 빈도 조절
- 거래비용을 줄이는 실행 전략
- 시장 국면별 전체 노출 조절

강화학습이 바로 맡기 위험한 영역:

- 전체 계좌 실전 주문
- 고빈도 단타
- 레버리지 확대
- 손절 규칙 자동 변경

강화학습 보상 함수 예시:

```text
reward =
  초과수익
  - 거래비용
  - 슬리피지
  - 회전율 패널티
  - 최대낙폭 패널티
  - 벤치마크 대비 부진 패널티
```

강화학습은 모의투자 계좌에서 6~12개월 이상 검증한다. 실전 투입하더라도 처음에는 전체 자산의 아주 작은 비중만 사용한다.

## 8. 수학적 판단 기준

### 8.1 정확도보다 기대값

정확도 55%가 돈을 번다는 뜻은 아니다.

중요한 것은 기대값이다.

기대값은 비용을 뺀 뒤 계산해야 한다.

```text
EV = p * 평균이익 - (1 - p) * 평균손실 - 거래비용 - 슬리피지
```

뜻:

- `EV`: 한 번 거래할 때 기대되는 평균 수익
- `p`: 이길 확률
- `평균이익`: 이긴 거래의 평균 수익
- `평균손실`: 진 거래의 평균 손실
- `거래비용`: 수수료, 세금, 환전 비용
- `슬리피지`: 예상 가격과 실제 체결 가격 차이

예시:

```text
승률: 45%
평균이익: 5%
평균손실: 2%
거래비용: 0.2%
슬리피지: 0.1%

EV = 0.45 * 5 - 0.55 * 2 - 0.2 - 0.1 = 0.85%
```

승률이 낮아도 벌 수 있다.

반대 예시:

```text
승률: 60%
평균이익: 1%
평균손실: 2%
거래비용: 0.2%
슬리피지: 0.1%

EV = 0.60 * 1 - 0.40 * 2 - 0.2 - 0.1 = -0.5%
```

승률이 높아도 잃을 수 있다.

실전 후보는 단순히 `EV > 0`만 보면 안 된다. 거래 횟수가 적으면 운 좋게 좋아 보일 수 있다. 초반 기준은 보수적으로 둔다.

```text
최근 out-of-sample 거래 100건 이상
비용 차감 후 EV > 0
벤치마크 대비 초과수익도 양수
```

AI 투자 보조 모드에서는 거래 횟수만 보지 않고 추천 강도별 성과도 따로 본다.

```text
AI 점수 90점 이상 추천군의 성과
AI 점수 80~90점 추천군의 성과
AI 점수 70~80점 추천군의 성과
AI 점수 70점 미만 추천군의 성과
```

좋은 AI라면 높은 점수를 준 종목군이 낮은 점수를 준 종목군보다 실제 성과가 좋아야 한다. 전체 평균 수익이 좋아 보여도 점수와 성과가 따로 놀면 투자 전문가로 쓰면 안 된다.

### 8.2 포지션 크기

모델이 확신한다고 몰빵하면 안 된다.

이론적으로는 축소 켈리 방식을 쓸 수 있다.

```text
비중 = k * 비용 차감 예상수익 / 변동성^2
```

하지만 이 공식은 추정이 조금만 틀려도 비중이 과하게 커질 수 있다. 군 복무 중에는 수학적으로 예쁜 비중보다 망하지 않는 제한이 더 중요하다.

초기 실전 비중은 아래처럼 단순 제한을 우선한다.

```text
AI 보조 매매 계좌: 전체 투자 가능 자금의 20~30%
종목 1개 기본 비중: 3~5%
강한 확신 + 검증된 전략: 종목 1개 최대 7%
섹터 1개 최대 비중: 25%
AI 보조 매매 계좌의 전체 주식 노출: 최대 70%
현금: 최소 30%
레버리지/미수/신용: 금지
```

여기서 전체 투자 가능 자금은 생활비, 비상금, 장기 보유 자산을 제외하고 실제로 위험을 감수할 수 있는 돈만 뜻한다. AI 보조 매매 계좌는 그중 일부만 사용한다.

`k`는 보수적으로 둔다.

- 연구 단계: 0
- 모의투자: 0
- 사람 승인 기반 소액 실전: 0.10~0.20
- 충분한 검증 후: 최대 0.30

완전 자동 주문에 가까워질수록 `k`를 낮춘다. 사람 승인 기반이면 조금 더 열어둘 수 있지만, AI가 스스로 주문하는 구조라면 초보자는 0.10을 넘기지 않는 것이 좋다.

### 8.3 AI 추천 품질 검증

AI를 투자 전문가처럼 쓰려면 "말을 그럴듯하게 하는지"가 아니라 "추천 품질이 실제로 개선되는지"를 봐야 한다.

최소 검증 항목:

- 추천 점수와 실제 수익률의 관계
- 추천 점수와 최대낙폭의 관계
- 추천 점수와 손절 발생률의 관계
- AI가 낸 반대 근거가 실제 손실 원인과 맞았는지
- 같은 데이터를 다시 넣었을 때 추천이 크게 흔들리는지
- 출처 없는 주장이 투자 의견서에 섞였는지

기본 합격 기준:

```text
상위 점수 추천군이 하위 점수 추천군보다 성과가 좋음
비용 차감 후 기대값이 양수
벤치마크 대비 초과수익이 양수
최대낙폭이 사전에 정한 한도 안에 있음
확신도 70% 구간의 실제 성공률이 70% 근처에 있음
```

확신도 검증은 특히 중요하다. AI가 매번 자신 있어 보이지만 실제로는 맞히지 못한다면, 그 AI는 투자 전문가가 아니라 말 잘하는 알림 도구일 뿐이다.

### 8.4 추천 점수별 행동 기준

AI가 추천해도 바로 매수하지 않는다. 점수별로 행동을 나눈다.

```text
70점 미만: 거래 금지
70~80점: 관심종목
80~90점: 소액 매매 후보
90점 이상: 실제 매매 검토
```

점수가 높아도 아래 조건 중 하나라도 걸리면 보류한다.

- 반대 근거가 강함
- 거래량이 부족함
- 실적 발표나 큰 이벤트 직전이라 변동성이 과함
- 같은 섹터에 이미 많이 노출됨
- 손절 기준이 너무 멀어서 손익비가 나쁨
- 모델 점수는 높은데 뉴스/공시 근거가 빈약함

## 9. 검증 체계

### 9.1 금지되는 검증

아래 방식은 하면 안 된다.

```text
2015~2025 전체 데이터로 학습
2015~2025 전체 데이터로 성과 확인
```

이건 답안지를 보고 시험을 치는 것과 같다.

### 9.2 Walk-forward validation

실제에 가까운 검증은 이렇게 한다.

```text
2015~2018 학습 -> 2019 테스트
2016~2019 학습 -> 2020 테스트
2017~2020 학습 -> 2021 테스트
2018~2021 학습 -> 2022 테스트
2019~2022 학습 -> 2023 테스트
```

각 시점에서 실제로 알 수 있었던 과거만 사용한다.

### 9.3 최소 누수 방지 규칙

금융 데이터는 미래 정보가 새기 쉽다. 초반에는 복잡한 논문 기법을 전부 넣기보다 아래 규칙부터 지킨다.

- 테스트 구간은 학습에 절대 넣지 않는다.
- 마지막 1년은 최종 시험지로 남겨두고, 모델 개발 중에는 보지 않는다.
- 10일 보유 전략이면 테스트 구간 앞뒤 최소 10거래일은 학습에서 제외한다.
- LLM 이벤트 피처는 `available_at` 이후에만 사용한다.
- 실적, 재무제표, 애널리스트 변경은 발표 시각 기준으로 정렬한다.

테스트 구간 앞뒤를 비우는 이유는 라벨이 겹치기 때문이다. 예를 들어 10일 보유 라벨을 만들면 오늘 샘플과 내일 샘플이 거의 같은 미래 가격을 공유한다. 이걸 그대로 학습하면 성과가 실제보다 좋아 보일 수 있다.

### 9.4 반드시 포함할 비용

백테스트에는 아래 비용이 들어가야 한다.

- 매수/매도 수수료
- 세금
- 환전 비용
- 슬리피지
- 체결 실패
- 거래정지
- 유동성 부족

비용 없는 백테스트는 거의 쓸모없다.

### 9.5 성과 지표

최소 지표:

- CAGR: 연평균 수익률
- MDD: 최대낙폭
- Sharpe ratio
- Sortino ratio
- Calmar ratio
- turnover: 회전율
- hit ratio: 승률
- average win/loss: 평균 이익/손실
- exposure: 시장 노출
- benchmark excess return: 벤치마크 대비 초과수익

중요한 것은 절대 수익만 보는 것이 아니다. SPY, QQQ, 동일가중 유니버스 대비 얼마나 잘했는지 봐야 한다.

### 9.6 지금은 제외할 고급 항목

아래 항목은 중요하지만 초반 필수는 아니다. 먼저 기본 검증을 제대로 만든 뒤 붙인다.

- Deflated Sharpe Ratio
- PBO
- 완전한 purged k-fold cross-validation
- 공분산 행렬 기반 최적 포트폴리오

이것들을 처음부터 넣으면 시스템이 너무 복잡해진다. 초반 목표는 "논문 수준 최적화"가 아니라 "미래 정보 누수 없는 재현 가능한 검증"이다.

### 9.7 과최적화 방지 규칙

과최적화는 과거 데이터에만 너무 잘 맞춘 상태를 말한다. 쉽게 말해 지난 시험 답안지를 외운 것이다. 실전에서는 망가질 가능성이 높다.

초반에는 아래 규칙만 지켜도 큰 사고를 줄일 수 있다.

- 매개변수를 자주 바꾸지 않는다.
- 한두 종목에서만 잘 되는 전략은 실전 후보에서 제외한다.
- 한 해에만 성과가 몰린 전략은 실전 후보에서 제외한다.
- 거래 횟수가 너무 적은 전략은 "좋아 보임"으로만 기록한다.
- AI에게 같은 결과를 반복해서 고치게 하며 성과를 맞추지 않는다.
- 마지막 1년 테스트 결과는 모델 개발 중에 보지 않는다.
- 전략 설명이 너무 복잡해지면 단순한 기준 모델과 다시 비교한다.

좋은 전략은 모든 구간에서 최고일 필요는 없다. 대신 여러 구간에서 무너지지 않아야 한다.

## 10. 위험관리와 킬스위치

### 10.1 절대 손실 기준만 쓰면 안 된다

월 -5% 손실이면 무조건 정지하는 방식은 너무 단순하다.

예를 들어 시장이 -10% 빠졌는데 전략이 -5%라면, 전략은 오히려 잘한 것이다.

그래서 킬스위치는 네 가지를 함께 봐야 한다.

```text
절대 손실
+ 벤치마크 대비 상대 성과
+ 모델 이상 징후
+ 실행/데이터 오류
```

### 10.2 벤치마크 상대 킬스위치

벤치마크 후보:

- SPY: 미국 대형주 기준
- QQQ: 나스닥 성장주 기준
- IWM: 중소형주 기준
- 동일가중 유니버스: 내가 거래 가능한 종목 전체를 같은 비중으로 산 기준

정지 조건 예시:

```text
20거래일 초과수익 < -5%
또는 20거래일 초과수익 z-score < -2
또는 전략 MDD가 벤치마크 MDD보다 5%p 이상 나쁨
```

초과수익:

```text
초과수익 = 전략수익률 - 벤치마크수익률
```

처음에는 이 단순식으로 충분하다. 나중에 전략이 커지면 베타 조정 alpha를 쓴다. 베타는 내 전략이 벤치마크와 얼마나 같이 움직이는지 보는 값이다.

```text
alpha = 전략수익률 - beta * 벤치마크수익률
```

초반에는 `초과수익`, 고도화 단계에서는 `alpha`를 킬스위치 기준으로 쓴다.

### 10.3 절대 안전장치

상대 성과와 별개로 계좌 보호용 절대 기준도 필요하다.

예시:

- 하루 계좌 손실 -3%: 신규 주문 중지
- 전체 계좌 손실 -10%: 포지션 절반 축소
- 전체 계좌 손실 -15%: 모든 신규 주문 정지
- 한 종목 비중 7% 초과 금지
- AI 보조 매매 계좌의 전체 주식 노출 70% 초과 금지
- 레버리지, 미수, 신용 금지

### 10.4 모델 이상 감지

모델이 예전과 다르게 행동하면 멈춰야 한다.

정지 조건 예시:

- 예측 확률 분포가 평소와 크게 달라짐
- calibration 붕괴: 70% 확신 구간의 실제 성공률이 크게 하락
- 신호 개수가 평소보다 3배 이상 증가
- 특정 섹터에만 과도하게 쏠림
- 최근 30일 거래의 기대값이 음수로 전환

calibration은 모델의 확신이 실제와 맞는지 보는 것이다. 예를 들어 모델이 "성공 확률 70%"라고 말한 거래들이 실제로 70% 정도 성공해야 한다.

### 10.5 데이터/API 오류 감지

주문 전 반드시 막아야 하는 오류:

- 가격 데이터 누락
- 전일 대비 비정상 가격 변화
- 거래량 0인데 거래 가능하다고 표시
- 같은 종목 중복 주문
- 주문 후 체결 확인 실패
- API 응답 지연
- 서버 시간과 거래소 시간 불일치

## 11. 실전 운영 방식

군 복무 중 실전 운용은 매일 장중 대응이 아니라 장 마감 후 연구와 다음날 제한 주문 중심이어야 한다.

권장 루틴:

```text
장 마감 후:
데이터 업데이트
피처 생성
모델 예측
후보 종목 생성
위험관리 필터 적용
AI 투자 의견서 생성
주문 후보 목록 저장

장 시작 전:
주문 가능 여부 재확인
가격/스프레드/거래량 확인
사람 승인 여부 확인
승인된 건만 제한가 주문

장중:
신규 판단 최소화
위험 조건 위반 시 자동 정지

주 1회:
성과 리포트 확인
이상 거래 확인

월 1회:
모델 재학습 후보 생성
검증 통과 모델만 배포
```

군 복무 중에는 매일 길게 판단하기 어렵다. 그래서 AI 의견서는 짧고 반복 가능한 형식이어야 한다. 매번 새로운 말투로 긴 보고서를 쓰는 것보다, 같은 항목을 꾸준히 채우는 편이 더 좋다.

## 12. 18개월 로드맵

### 0~2개월: 데이터와 백테스트 기반

목표:

- 가격 데이터 수집 파이프라인 구축
- 데이터 정합성 검사
- 간단한 백테스트 엔진
- 수수료/슬리피지 반영
- SPY/QQQ/동일가중 벤치마크 구축

완료 기준:

- 같은 데이터로 같은 결과가 재현됨
- 비용 포함 백테스트 가능
- 생존자 편향 문제가 문서화됨

### 2~5개월: Supervised model 1차

목표:

- baseline 전략 구축
- triple-barrier labeling
- LightGBM/XGBoost 모델
- walk-forward validation
- meta-labeling 초안

완료 기준:

- 단순 baseline보다 나은 구간이 있음
- 성과가 특정 1년 구간에만 몰려 있지 않음
- 거래비용 포함 후에도 기대값이 양수

### 5~8개월: AI 투자 의견서와 LLM 대안 데이터

목표:

- 뉴스/공시/실적콜 수집
- LLM 구조화 스키마 설계
- 이벤트 피처 생성
- 가격 데이터와 시간 정렬
- 이벤트 전후 성과 분석
- 종목별 AI 투자 의견서 생성
- 추천 점수별 성과 추적
- 고정 의견서 양식과 점수 기준표 적용
- 같은 입력 재실행 테스트

완료 기준:

- LLM 출력이 JSON 스키마로 안정적으로 저장됨
- 같은 문서를 여러 번 돌렸을 때 결과 차이가 관리됨
- 이벤트 피처 추가 후 out-of-sample 성과 개선 여부 확인
- AI 점수 상위군이 하위군보다 실제 성과가 좋음
- AI 의견서에 핵심 근거와 반대 근거가 모두 기록됨
- 같은 입력을 다시 분석했을 때 추천 결론이 크게 흔들리지 않음

### 8~12개월: 강화학습 Paper Lab

목표:

- 모의투자 환경 구축
- transaction cost 포함 reward 설계
- 포지션 사이징/리밸런싱 RL 실험
- supervised model과 RL 비교

완료 기준:

- RL이 비용 없는 환경에서만 좋아 보이는지 확인
- reward hacking 여부 점검
- 모의투자에서 최소 3개월 이상 자동 실행

reward hacking은 모델이 실제 돈을 버는 대신 점수 계산식의 허점을 이용하는 문제다.

### 12~18개월: 사람 승인 기반 반자동 실전과 장기 검증

목표:

- AI 보조 매매 계좌 운용
- 사람 승인 기반 소액 실전
- RL은 계속 paper trading
- 월간 모델 재학습 프로세스
- 킬스위치 자동화
- 리포트 자동화

완료 기준:

- 실전 주문 오류 없음
- 킬스위치가 실제로 작동함
- 성과가 벤치마크 대비 추적됨
- AI 추천 점수와 실제 성과의 관계가 추적됨
- AI 의견서 버전과 사후 성과가 함께 저장됨
- 모델 교체가 수동 승인 후에만 진행됨

## 13. 실전 투입 기준

### 13.1 모의투자 통과 조건

최소 조건:

- 모의투자 3개월 이상
- 거래비용 포함
- 주문 실패 처리 검증
- 중복 주문 없음
- 일별 리포트 자동 생성
- 킬스위치 테스트 통과
- AI 추천 점수별 성과 기록
- AI 의견서의 반대 근거 기록
- AI 의견서 양식과 점수 기준표 고정
- 같은 입력 재실행 테스트 통과

### 13.2 사람 승인 기반 소액 실전 조건

소액 실전은 AI 보조 매매 계좌 안에서 시작한다. AI 보조 매매 계좌는 전체 투자 가능 자금의 20~30%를 넘기지 않는다. 처음에는 그 안에서도 절반 이하만 사용하고, 주문은 사람이 승인한 건만 실행한다.

조건:

- 백테스트와 모의투자 모두 통과
- AI 점수 상위군이 하위군보다 성과가 좋음
- 추천 이유와 반대 이유가 모두 저장됨
- 추천 점수 산정 기준이 바뀌지 않고 기록됨
- 추천 후 5일, 10일, 20일 성과가 자동 저장됨
- 실전 API 주문/취소/체결 확인 테스트 완료
- 서버 장애 시 신규 주문 중지
- API 키가 코드에 저장되지 않음
- 알림 시스템 작동
- 시장가 주문 금지, 제한가 주문 우선
- 레버리지, 미수, 신용 금지

### 13.3 자동 주문 전환 조건

자동 주문은 목표가 아니라 옵션이다. 사람 승인 기반으로 충분히 잘 작동하면 굳이 자동 주문으로 빨리 넘어갈 필요가 없다.

자동 주문을 검토하려면 최소한 아래 조건을 만족해야 한다.

- 사람 승인 기반 실전에서 3개월 이상 주문 오류 없음
- 킬스위치가 실제 상황 또는 모의 장애에서 작동함
- AI 추천 점수와 성과 관계가 유지됨
- 손실이 사전에 정한 한도 안에 있음
- 자동 주문 한도가 증권사/브로커 설정에서도 제한됨
- 자동 주문 비중은 AI 보조 매매 계좌의 일부로만 제한됨

### 13.4 모델 교체 조건

새 모델은 바로 실전에 넣지 않는다.

배포 조건:

- 기존 모델보다 out-of-sample 성과가 좋음
- 거래 횟수가 비정상적으로 늘지 않음
- 특정 종목/섹터에 과도하게 의존하지 않음
- 벤치마크 대비 성과가 개선됨
- paper trading에서 최소 1개월 이상 확인됨

## 16. 최종 운영 원칙

이 시스템의 목표는 "AI가 돈을 벌어준다"가 아니다.

목표는 아래다.

```text
1. 과거 데이터에서 착시를 최대한 제거한다.
2. 텍스트/이벤트 데이터를 LLM으로 구조화한다.
3. 모델은 기대값이 있는 거래만 고른다.
4. 위험관리 엔진은 모델보다 우선한다.
5. 강화학습은 초반부터 연구하되 실전 투입은 오래 검증한다.
6. 성과는 절대수익이 아니라 벤치마크 대비로 본다.
7. 군 복무 중에는 고빈도보다 저빈도/자동정지/설명가능성이 중요하다.
8. AI 의견서는 고정 양식, 고정 점수 기준, 사후 채점으로 일관성을 관리한다.
```

최종 형태는 다음과 같다.

```text
실전 계좌:
검증된 supervised model + 일관된 AI 의견서 + 강한 risk engine + 제한 주문

연구 계좌:
LLM 대안 데이터 실험 + 강화학습 paper trading

운영 방식:
월 1회 모델 재학습 후보 생성
AI 의견서 품질과 점수별 성과 추적
검증 통과 모델만 수동 승인 후 배포
이상 징후 발생 시 자동 정지
```

이 방향이면 네 기대인 "지금까지의 모든 차트 데이터를 보며 스스로 학습하는 시스템"을 현실적인 형태로 만들 수 있다. 다만 "스스로 학습"은 실전 중 마음대로 변하는 AI가 아니라, 정해진 검증 절차를 통과한 모델만 배포되는 통제된 학습 시스템이어야 한다.
